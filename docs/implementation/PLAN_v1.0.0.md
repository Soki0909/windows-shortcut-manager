## Discoveries

- 継続レビューでint32範囲外のversion headerが破損JSON扱いへ抜ける境界を発見し、#125を追加。小数・指数・極端な数値も未対応として停止し、診断文字数を制限した。

- `set_goal`というツール名は提供されていないため、同等の`create_goal`で目標を設定済み。
- #1のチェック状態と公開後記録が古い。#120を通じて実際のIssue/CI/公開/製品更新結果と同期する。
- 自動バックアップ整理はフォルダ内の全ZIPを対象としている。手動・不明・外部コピーを自動削除してはいけない (#41)。
- 拡張更新は直接上書きで中断時に混在し得る (#119)。個人環境を故障注入fixtureに使わない。
- サンドボックスでは.NETのWindowsサービス照会と.git書込みが制限された。通常権限でテスト/取得を実行する。

## Decisions

- 所有者指示（2026-11-02追記）: 関連Issueは機能単位にまとめて実装・検証・PR・main統合する。細かいIssueごとのPR/CI待ちを減らす。現在の状態表示・操作可否・監査・選択同期と、関連する編集フォーム改善を1つの操作性マイルストーンにまとめる。

- 所有者指示（2026-11-02）: 各変更では確認が必要な項目だけを検証する。毎回の全体テストは行わず、広い相互影響がある統合時や正式リリース前に限定する。CIの既存必須チェックは維持する。

- 要件と既存ADRを維持。新しい常駐機構、hook、host権限、個人設定のDebug流用は導入しない。
- P0は既存版で解消済み。未解決の安全性、使える導入/操作、配布と検証を優先し、P3調査は正式版の必須条件へ自動昇格させない。
- ライセンスは所有者の「推奨でよい」に基づきMITを採用。依存物の条件は別途保持する。
- 自動バックアップにはZIP名・SHA-256のreceiptを付け、検証できるapply/restore生成分だけを保持管理する。旧版・手動・外部コピー・改変・不明ZIPは自動削除しない。
- CLIの失敗終了コード不足を新規Issue #121へ登録。JSON互換を維持し、引数/結果保存不能を含めて非ゼロ終了とする。
- 証明書・Storeアカウント/審査・別OS/配列の実機・第三者ユーザーテスト等は実在する前提を確認し、未実施を合格扱いしない。
- マイルストーンごとに検証してmainへ統合する。利用中環境はリリース用Setupでのみ更新し、更新前バックアップを保持する。
