# アプリの起動方法・引数・作業フォルダ / #26/#27

| 方法 | 実際に開く対象 | 追加引数 | 作業フォルダ |
|---|---|---|---|
| ファイルを直接起動 | 指定したファイル | 入力した文字列を渡す | 明示値、空欄ならファイルのあるフォルダ |
| 既存のWindowsショートカット | Explorerへ元の.lnkパスを引用して渡す | 元リンク自身の指定。Managerの追加引数は渡さない | 元リンク自身の指定。Managerの値はExplorer側の値で、元リンクへの上書き指定ではない |
| アプリURI / shell:AppsFolder | ExplorerへURIを引用して渡す | URI自身の内容。Managerの追加引数は渡さない | Managerの値はExplorer側の値。URI先アプリへの継承は保証しない |

既存の.lnk/URIに追加引数が保存されていても消去しない。フォームでは読取り専用にし、起動に使わない理由を編集時とテスト前に表示する。種類/モードの切替で別の方式へ旧引数を転送しない。元の.lnkを平坦化、改変、HotKey解除しない。

## 入力検証と確認

- ローカルファイル/作業フォルダは、ドライブまたは共有名から始まる絶対パスを指定する。入力値自体に引用符を付けない。相対パス、フォルダをファイルとして選んだ場合、ファイルを作業フォルダとして選んだ場合、存在しない/照会できない先を区別して案内する。
- 空白・日本語のパスとUNC共有パスは許可する。入力中はファイル/ネットワーク/登録状態の照会を行わず、明示的な「入力を再確認」（F5）や有効な項目の保存時に照会する。共有先への接続・アクセス権は必要で、存在/権限の照会失敗を利用可能と断定しない。
- URIはF5/保存時と起動プレビューでWindows登録を照会する。登録あり/見つからない/照会不能を区別するが、結果だけで起動成功や失敗を断定しない。shell名前空間やfile URIは通常のscheme登録判定から分ける。未登録に見えるURIを勝手に書換えたり削除したりしない。
- 解決済み実行先・実際に渡す引数・作業フォルダを起動前に表示する。表示だけでは起動せず、「実行する」を明示して初めて起動する。小画面で長い注意文がある場合も、全体スクロールで実際の値とボタンへ到達できる。

## 実行検証の範囲

無画面・非常駐のテスト専用WinExeプローブが、自分のnonceフォルダへ新規レポートだけを書いて終了する。直接起動で日本語/空白/引用符/末尾バックスラッシュ/空引数、元lnk経由で元の引数/作業フォルダとbyte不変を確認する。HotKeyを登録しない。

使い捨てGitHub Windows hosted runnerだけで、nonce付き独自URI登録と一時SMB共有を作り、実際のURI引数と日本語/空白を含むUNCパスの起動/作業フォルダを確認する。URI keyとSMB shareは所有marker/description一致を確認して整理し、既存項目は上書きしない。ローカルでは明示skipとし、環境変数を偽装して実行しない。

このプローブは製品に同梱せず、外部のLINE/Slack/ChatGPT/Outlookや任意のネットワーク/認証方式をすべて確認した証拠とはしない。対応環境の広い検証は#54、元リンクの特殊な昇格/Store条件は#32で追跡する。

参考: [Windowsアプリ登録](https://learn.microsoft.com/en-us/windows/win32/shell/app-registration)、[URI activation](https://learn.microsoft.com/en-us/windows/apps/develop/launch/reserved-uri-scheme-names)。実際の結果はVERIFICATIONへ記録する。
