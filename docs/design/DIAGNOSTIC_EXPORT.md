# 報告用の診断エクスポート / #58

「確認と復旧」→「報告用の診断を確認・保存…」で、画面を開いた時点の診断を確認し、新しいJSONファイルへ保存する。送信・Issue作成・クリップボードへの自動コピーは行わない。

## 既定の内容と境界

`ShortcutManager.Diagnostic.v1`は、製品/Debug版、対応schema/protocol、Windowsの数値版、実行中.NETの数値版、プロセスarchitecture、取得時刻、状態のbool、候補の種類別件数、既知の検証コード別件数、直近に観測した監査差分件数、既存スキャンの件数/読取失敗/未確認数を含む。

名前、HotKeyの文字、Guid、拡張ID、パス、URL、引数、監査の実際値/期待値、例外本文、ログ原文、バックアップやconfigの内容は含めない。匿名化は任意テキストへの正規表現置換ではなく、許可した値だけを新しい構造へ組み立てて行う。未知の検証コードは`other-validation-error`へまとめる。

ログのERROR呼出し回数と最後の例外種別に対応する固定コードは、このManagerプロセスの起動中だけを対象とする。元の例外型名やmessageを出力しない。ログ保存失敗中でも記録できる。ERRORとして記録されなかった失敗、前回起動や過去ログのエラーまで取得したとは扱わない。`None`は全操作成功の証明ではない。

診断作成は新たな走査・監査・外部パスへの存在照会を行わず、候補・保存設定・ファイルを変更しない。検証は候補の構造/入力値だけで、起動先ファイルの存在確認ではない。未実施の走査は`scan`を省略し、差分0件や`SavedLinksVerified=false`を監査成功と取り違えない。保存や読戻しから物理HotKeyの成功を推定しない。

## 補足・確認・保存

利用者が明示した場合だけ、8000文字までの補足を追加する。補足は自動マスクしないため、入力欄とプレビューで個人情報を自分で確認する。オフに戻すと出力から除去し、診断は既定の状態へ戻る。補足の追加/変更/除去は確認済み状態を解除する。

保存前に全文を確認したチェックが必要。保存するのは表示したJSONそのもの。UTF-8 BOMなしで同じフォルダの新規一時ファイルへ全量を書き、flush後に非上書きのrenameで公開する。同名ファイル/フォルダがあれば停止し、別名を求める。保存先が競合しても上書きしない。一時ファイルは自分で作成したものだけを整理する。

診断全体は128 Ki文字を上限とし、親フォルダは自動生成しない。画面内と画面全体のスクロールで小画面でも全文/確認/保存へ到達可能にする。これらは診断の保存だけで、送信は利用者が別途行う。

## 検証

隔離fixtureで、秘密の名前/URL/ID/パス/未知コードの非出力、件数/既知コード保持、スナップショット固定、補足の明示追加/除去/上限、未実施チェックの区別、正確なUnicode保存、既存ファイル保持、同時保存、失敗時の中間物非公開を確認する。ViewModel経由で候補と全ファイルのbyte不変も確認する。

非表示WPF描画/制御検査では、補足変更時の再確認要求と小画面スクロールを確認する。これは実際のNarrator/Windows高コントラスト/物理キーの検証の代わりではない。
