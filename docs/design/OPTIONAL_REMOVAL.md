# 管理ショートカットの解除とローカルデータの削除（#52）

## 確認した現状

公式アンインストーラーは本体を削除する。対話実行では設定、バックアップ、管理ショートカットキーを保持する旨を案内し、キャンセルを既定にする。既存Setupからの更新、アンインストール、再導入時の保持は、使い捨てWindows runnerのライフサイクル検証で確認する。任意の完全削除は未実装である。

個別の解除は、Managerで割当を無効にして変更を反映すると実行できる。通常のバックアップZIPは保存済み設定、管理ショートカット、反映状態を対象とする。ログ、監査履歴、既存バックアップそのもの、編集中の設定も削除する場合は、ZIPだけでは元の状態を復元できない。

## 利用者が選べる操作

| 選択 | 効果 | 復元方法 |
| --- | --- | --- |
| 公式アンインストール | 本体を削除し、設定と管理ショートカットを保持する。対話実行とサイレント実行で保持範囲を揃える | Setupを再実行する |
| 管理ショートカットキーを解除 | 管理中の割当を無効にして反映する。割当の定義は保存する | 解除前のZIPを既存の復元画面でプレビューし、競合を確認して復元する |
| 確認済みのローカルデータを削除 | 対象一覧で承認したファイルを退避する。利用者が最後に消去を選ぶと退避済みファイルを削除する | 消去前は退避を取り消す。消去後は別の場所へ保存した削除前アーカイブから復元する |

Managerの「削除の準備」で、現在の保存先、管理フォルダ、割当の件数、未保存の変更を示す。未保存の変更は利用者が反映するか破棄するまで、削除の確認へ進めない。各選択肢は未選択で開き、対象と復元方法を操作ごとに確認する。データ削除は、正常な反映または読取り監査で管理リンクが残っていないと確認した後に選べる。設定だけを消して有効な管理リンクが残る状態を防ぐ。

解除は保存済みの割当をすべて無効にした候補を既存のApplyへ渡し、所有マーカー、外部競合、バックアップ、ステージング、反映後の読戻しを通す。解除前に利用者が選んだ別の場所へバックアップZIPを書き出し、読戻しとハッシュを確認する。解除前ZIPにも手順2の保存先検査と新規作成を適用する。データ削除と続けて行う場合、解除前ZIPと解除後の保存データを収める削除前アーカイブの両方が必要になる。解除済みの表示は保存された管理リンクの検証結果に基づく。物理キーの動作は既存の確認手順に従い、Explorerの再読み込みは利用者の同意を得る。

データの退避・消去・取り消しと検証を終えた後、利用者は公式アンインストールを実行できる。退避中に本体を削除した場合は、再導入後に復旧画面を表示する。Setupのカスタム操作からデータを消去する機能は設けず、同じ準備をポータブル版にも適用する。

## 確認画面に出す削除対象

- 現在のエディションの保存先と反映先を `ApplicationPaths` と保存済み設定から決定し、実際のパスを画面に表示する。開発版の反映先にはADR-007を適用する。他エディションの保存先や管理フォルダに解決されるパスは拒否する。保存済みの反映先とディスク上の反映状態が食い違う場合は、両方を調べて旧反映先にも管理リンクがないと確認する。設定や反映状態が読めず反映先を確定できない場合は、復旧してから削除へ進む。
- `ApplicationPaths` の設定と反映状態、`AuditControlStore` の監査設定、修復試行記録と監査履歴、`FileLogger` のログとローテーション分を、実際の保存先と対応する形式で識別する。監査履歴は画面の表示上限を超える過去分も対象確認する。名前だけ一致するファイル、形式不明、破損、照会不能のファイルは、残る理由とともに表示する。個々のファイルが製品による保存物だと確認できない場合は保持する。
- 自動バックアップはZIPとreceiptを一組にし、`BackupService` のreceipt照合と `BackupArchive` の読取りを通す。孤立したreceiptは保持する。手動・旧形式・receipt不明のZIPは、保存先のバックアップ用フォルダ内で読み取れるものを利用者が個別に選べるようにし、消去前に退避する。利用者が別の場所へ保存したZIPと削除前アーカイブは対象外とする。
- 未完了の反映・復元・削除トランザクションがあるときは、解決するまで新しい削除を開始できない。復旧用データはその復旧手順が管理する。
- 管理フォルダと所有マーカーは保持する。管理フォルダは既存の所有判定を通し、マーカー以外のファイルやサブフォルダが残っている場合はデータ削除を開始しない。ローカルデータ側の空フォルダは残ってよい。再帰的なディレクトリ削除は行わない。
- 管理外の割当、元の.lnk/.url、外部BAT/CMD、他エディション、Chrome拡張やそのデータ、他アプリ、Setupが識別できない残留ファイルは残る。Chrome側の履歴管理や拡張の削除はChromeで操作する。残留項目があるときは、削除結果に項目と理由を示す。

## 確認・退避・消去

1. プレビューで対象ごとのパス、種類、サイズ、SHA-256、所有判定結果と残る項目を示す。この段階ではファイルを変更しない。確認は現ユーザーと現在のエディション、対象一覧、ハッシュ、設定と管理フォルダの状態に結びつける。
2. 利用者が一覧を承認した後、対象ファイル全部を含む削除前アーカイブを、利用者が選んだ別の場所に新規作成する。元のエディション、ファイルの種別、相対パス、サイズとSHA-256を収録する。既存ファイルを上書きせず、保存候補が製品の保存先、管理フォルダ、退避先やその別名の配下に入る場合は拒否する。保存後は全エントリを読み直し、承認済み一覧とSHA-256が一致することを確認する。作成、検証、容量確認のどれかに失敗した場合は退避に進まない。
3. 対話型の削除処理は現エディションのインスタンスリースとApplyミューテックスを使い、プレビュー内容とアーカイブ全体のハッシュを再確認する。ログや監査の書込みを止める。ファイルとルートの実体を確認し、パス途中のreparse point、複数のハードリンク、照会不能、プレビュー後の置換や変更を検出したら停止する。ハッシュ確認後にパスを開き直して別のファイルを移動・削除する競合を防ぐため、検査した同じファイルハンドルに対して操作し、親ディレクトリの差替えも防ぐ。
4. 対象を同じボリュームの専用の退避領域へ、上書きなしで個別に移す。起動時に確定できるエディション別の場所へ、承認済みファイルの相対パス、退避先、実体情報、ハッシュとアーカイブの識別情報を記録し、最初の移動前にジャーナルをフラッシュする。進み具合を記録し、移動直後にハッシュを読み戻す。移動途中の中断は、各項目の元と退避先を照合して取り消す。退避済みで元が空いている項目だけを上書きなしで戻す。両方に存在する、両方に存在しない、実体やハッシュが違う場合は停止し、復旧に使えるファイルを保持する。
5. 全件の退避を確認したら、取り消しと確定消去を選べるようにする。この段階で本体を再起動した場合も確認画面に戻る。確定直前に削除前アーカイブと退避内容を再確認し、確定の記録を先に永続化する。確定後の中断ではジャーナルに載る検証済みの退避ファイルだけが消去対象になる。再開時にアーカイブや残りの退避ファイルを検証できない場合は停止する。結果では削除済みと保留を区別し、アーカイブと処理記録の保存先、再導入後の復元方法を表示する。
6. GUI、監査専用起動、CLIで、通常の設定読込みやファイル生成に先立って未完了の削除を確認する。復旧に必要な状態を曖昧にする書込みは復旧が終わるまで止める。削除前アーカイブの復元では、エディション、相対名・重複とWindows上の別名、形式、件数・合計サイズ上限、各SHA-256を検証し、現在エディションの正規の保存先をプレビューする。設定と管理リンクには既存の復元サービスを使う。保存済み設定や管理リンクの競合と外部キーの競合を事前に確認し、付随ファイルも含めた復元中断に備えてジャーナルを使う。反映状態は管理リンクに合わせて生成し、履歴内の旧パスを復元先に使わない。

削除操作は承認済みファイルの通常のファイル削除を意味する。別途保存したアーカイブ、OSのバックアップ、ストレージ上の消去履歴は管理対象に含めない。

## 実装・受け入れ確認

1. 読取り専用プレビューと所有判定を実装する。テスト用の保存先で、未知ファイル、古い反映先のリンク、旧バックアップ、外部ファイル、別のエディション、ジャンクションとハードリンク、確認後の変更と差替え、未保存候補、作成できないアーカイブを検証する。
2. 削除前アーカイブ、退避ジャーナル、復元の経路を実装する。ファイル移動ごとの障害とプロセス終了、退避後・確定前の再起動、復元先の競合、確認後のアーカイブ改変、確定消去中の再起動を検証する。承認していないファイルと削除前アーカイブのハッシュを比較する。
3. GUIを実装し、バックアップの保存、解除が不要な場合のデータ削除、取り消し、確定消去、再導入後の復元を操作する。既定アンインストールの保持テストは使い捨てWindows runnerで継続し、実機で代表の物理キー操作と削除後に残る項目を確認する。
