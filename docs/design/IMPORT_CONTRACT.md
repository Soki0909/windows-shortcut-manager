# 既存ショートカットの移行契約

移行は読取り専用の探索と候補設定の作成を分ける。元ファイルの削除・書換え・HotKey解除は行わない。

- `.lnk` は常にアプリの「既存のWindowsショートカット」方式で元パスを参照する。読み取れた実行先がexeでも平坦化しない。現在の読取りAPIでは、昇格・advertisedアプリ・AppUserModelID等を含めて単純exeと同等だと保証できないためである。元の引数・作業フォルダ・ウィンドウ状態などは元リンクをWindowsが解釈する。移行後も元リンクが必要で、移動・削除すると起動できなくなる。
- http/httpsの `.url` はWebサイトのURLを候補へ複製する。それ以外の形式や読取り失敗は移行不可として詳細を表示する。
- 元キーは複製先の空きとは限らない。選択範囲内の管理外ファイルに同じキーが残る場合はそのキーを選択不可にし、元パスを表示する。利用者が別のキーを明示的に選ぶまで候補を作らない。無効な候補定義は削除せず件数を示す。
- この画面の「空き」は今回読めた指定範囲内の結果である。他アプリの動的なキー取得を検出したとはしない。反映直前に既定範囲と今回選択した追加範囲を再確認し、新たな外部競合があれば元ファイルを変えずに停止する。追加の走査範囲は今回のManager起動中のみ保持し、設定schemaは変更しない。
- 既定範囲は共有/個人のスタートメニューとデスクトップ。利用者が選択を外す/別フォルダを追加できる。重複範囲を統合し、reparse pointとその配下の明示ルートは追跡しない。読取り失敗・アクセス不能・消失・除外は正常件数と区別する。一部未確認の場合は全件確認済みと表示しない。
- CLI `--scan` の `ok` はコマンド実行の成否、`complete` は指定範囲の走査・読取りがすべて完了したかを表す。`scanIssues`、`readFailureCount`、`items[].parseError`を併せて確認する。

通常/最小化の元lnkの読戻し、候補と解決後の元lnk参照、元ファイルのバイト不変は隔離fixtureで検証する。特殊なStoreアプリ等を利用中環境で起動した証拠とは区別する。安全な元キー解除GUIは #31 として別途扱う。
