# 日本語UIの用語と表示の境界

Issue #11。利用者向けの操作名と、保存・起動・Windowsへの反映・実際のキー動作を区別する。保存形式や通信仕様は変更しない。

| 用語・操作名 | 画面での意味 | 実装上の名前・補足 |
|---|---|---|
| 割当 | 名前・起動先・キーをまとめた1件 | ShortcutDefinition。Windowsの元ファイルと区別する |
| ショートカットキー | Ctrl + Alt + A–Zで対象を呼び出すキー | HotKey。通常画面で英語名を使わない |
| 候補に保存 | 編集・設定ダイアログから編集中の候補へ戻す | メモリ上の候補を更新する。設定ファイルやリンクへの保存ではない |
| 変更を反映 | 候補を検証し、現在をバックアップして設定と管理リンクへ保存 | Apply。主画面と初回ガイドで同じ操作名 |
| 未保存 | 候補に変更があり、まだ変更を反映していない | IsDirty / Unapplied Changes。状態コードは変更しない |
| 保存済み・反映未確認 | 設定とリンクは保存したが、Windows側のキー反映が未確認 | ShellReflectionPending。未保存と同義にしない |
| 実キー確認済み（今回の申告） | 利用者が実際にCtrl+Alt+文字キーを押して意図どおり動くと申告した | 対象のテストや保存・エクスプローラー再起動からは推定しない |
| 対象をテスト | 登録した対象を実際に起動する | Test / Test launch。BAT・アプリの処理も実行する。読取り専用の確認と区別する |
| 起動内容の確認 | 実行先・引数などを表示するだけ | Launch preview。実行は別ボタン「対象をテスト」 |
| 保存済みを読み直す | 設定ファイルから候補を読み直す | Reload。リンクの監査・修復・エクスプローラー再起動とは別 |
| 既存をスキャン | 指定した範囲の既存ショートカットを読み取る | Scan。「走査」と混在させない |
| 管理リンク | Managerが管理フォルダに生成するWindowsショートカット | .lnk。元ファイル・管理外のショートカットと区別する |
| 管理フォルダ | 管理リンクを置く場所 | 設定画面では「管理リンクのフォルダ」と内容を明示する |
| 監査 | 保存済み設定と管理リンクを照合する | Audit。候補は保持する。修復を伴う操作とは区別する |
| 修復 | 管理リンクを保存済み設定に合わせる | Repair。事前確認・バックアップ等の安全条件を維持する |
| エクスプローラー | デスクトップ・タスクバー・ショートカットを扱うWindowsの仕組み | Explorer。再起動に伴う影響を省略しない |
| 拡張メニュー | Chromeの拡張アイコンから開く一覧画面 | Popup。コード・ファイル名はそのまま |
| 復旧記録 | 中断した反映等を完全な状態へ戻すための記録 | journal。利用者に削除を促さない |
| Webサイト / アプリ / BAT / CMD / Chromeタブグループ | 対象の種類 | 設定enum値やProtocol値は翻訳しない |

## 画面での使い分け

- 共通の操作名と種類名は表示専用の小さい定数群 `UiText` から使う。状態コード、保存enum、JSONのプロパティ名、Protocolのaction、ログ書式は変更しない。
- 編集と設定の「候補に保存」は設定ファイル保存ではないことを説明する。主画面の「変更を反映」へ案内する。
- 初回ガイド・使い方・起動内容の確認・処理結果は、主画面の実際のボタン名で案内する。対象のテストには実行副作用があることを明示する。
- キー枠と一覧で同じ未保存状態を表すときは「未保存」を使う。保存後のWindows反映未確認や、実際のキー動作未確認は別の状態として残す。
- 「使い方」の「用語」タブで、この操作と状態の違いをオフラインで読める。
- URL、URI、BAT / CMD、Chrome、Windows、JSON等の識別に必要な名称は保持する。アプリURI等は入力欄の説明と詳細情報で例を示す。
- 診断JSON、例外の技術的詳細、ファイル名、パス、既存の履歴本文は正確さを優先し、任意の部分置換をしない。製品情報には設定形式・通信形式の技術名も併記する。

これは表示方針の記録であり、所有者の要件、保存形式、Windowsのキー動作保証を変更するものではない。
