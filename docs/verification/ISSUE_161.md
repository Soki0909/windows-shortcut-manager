# Issue #161 WPF資源テストの分離

2026-11-05のmain CIでは、配色テストのSTAスレッドが30秒以内に終了しなかった。ログに処理段階がなかったため、この実行がどこで停止したかは特定できていない。[失敗したCI](https://github.com/Soki0909/windows-shortcut-manager/actions/runs/41894393076)

- WPF資源テストを専用のSTA子プロセスへ移した。App.xamlの実資源から検査用辞書を作り、ホバーの入力条件だけをTagに置き換える。既存ボタンの可読性・無効状態、エラー表示、設定画面の色変更と、Dispatcher経由の配色更新・破棄後の動作を検査する。
- WPFはApplication構築時に起動処理をキューへ登録する。子プロセスは標準のApplicationで実資源を読み込む構成とし、製品の起動処理をテストから隔離した。
- 子プロセスが停止した場合は最後の処理段階、終了状態、標準出力と標準エラーを報告する。30秒で終了しない場合、テストが起動した子プロセスを停止して終了を確認する。
- 2026-11-17にSDK 10.0.404の対象テスト28件が成功。実資源の検査を3プロセスで連続実行し、Application構築後に意図的に停止したプロセスを監督側で終了できることと、次のプロセスが検査を完了できることを確認した。
