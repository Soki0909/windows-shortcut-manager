# ADR-015: インストーラー配置履歴による旧ファイル退避

Status: Accepted — 所有者の正式版/製品更新指示に基づき#56/#91へ対応。ADR-006の同一AppId・ユーザーデータ保持・非常駐を維持する。

Innoの通常配置だけでは新版からなくなったDLL等が残る。フォルダ一括削除や拡張子による削除はユーザー追加物を巻き込むため使わない。

- ビルド時に実publishの相対パスとSHA-256をUnicode INIへ記録し、Setup内に埋め込む。コードやRuntimeへの新しい依存を増やさない。ZIP版に自動整理は追加しない。
- Setupはファイル配置前に旧receiptを読み、配置後に旧だけに存在してhashが一致するファイルを、新規の`.shortcut-manager-retired-*`フォルダへコピー・再検証してから削除する。旧receiptも退避する。新しいreceiptはインストール先に結び付け、同じvolumeの一時ファイルから原子的に切り替える。
- receiptなしの旧版では所有ファイルを推測して削除しない。初回は現行配置の記録だけを作る。未知/破損/過大/重複/別保存先/途中変更のreceiptは自動整理せず原本を保持する。
- 改変された旧ファイル、記録にないユーザー追加物、古い不要フォルダは自動削除しない。保存/コピー/hash確認不能時も削除しない。退避物の自動保持数制限は設けない。
- 管理ショートカットのownership markerとは別の仕組みで、config、state、バックアップ、HotKey、Chrome storageは対象外。通常のInno uninstallはアプリとランチャーを削除し、これらのユーザーデータと旧payloadの退避を維持する。
- インストール先/新版配置先のreparseや照会不能は、配置を始める前に拒否する。古い不要ファイルのreparseは追跡せず保持する。相対パスはdot segment、絶対/ADS/制御文字、メタデータ用の予約名等を拒否する。
- 中断後に旧receiptが残っても、削除済みファイルは退避されている。再実行時は存在する一致分だけを扱い、不明分へ整理対象を広げない。退避の復元は別途の所有者確認付き手順とし、バックアップを黙って上書きへ戻さない。

receiptは同じWindowsユーザーが編集できるローカル所有記録であり、悪意ある同一ユーザーに対する認証境界とは主張しない。公開Setupの由来は別のhash/Authenticode/attestationで確認する。

検証は使い捨てWindows runnerに限定する。公開済み旧Setupのhash固定からの更新・保持と、実際にfile構成が異なるfixture Setup→新版、同じnative処理の保護境界を確認する。所有者PCへの開発Setup実行やHotKey物理入力をこのテストに含めない。
